= xstate: XState's state machines and actors for {cpp}
:toc: left
:toclevels: 1
:idprefix:
:sectanchors:
:example-caption!:
:attribute-missing: warn

xstate is a header-only port of https://stately.ai/docs/xstate[XState]
5.33.2, Stately's library of state machines and actors, to {cpp}20, one of
the libraries of https://github.com/webcpporg/webcpp[webcpp]. A machine is
loaded from the JSON config XState's `createMachine` takes, and run through
XState's pure functions or as an actor.

This page teaches xstate as Stately's documentation teaches XState: each
concept, why it exists, its smallest example, its variations and its rules.
Every program it shows was compiled and run, natively and for wasm32-wasip2
and wasm32-wasip3, and printed the output shown under it. Every program is
also proven against XState: its twin, the same program written for XState
5.33.2, prints the same output, or the output of a difference xstate makes
on purpose, unless it shows something XState does not have
(<<overview-fidelity>>). The <<reference,reference>> lists every name the
headers declare.

== Reference

Every name xstate declares, in the namespace `webcpp::xstate`, from the Doc
Comments of its headers: each class, function, type and enumerator with its
declaration, what it does, what it asks of its caller and how it fails, and
the part of XState 5.33.2 it ports. The other sections teach the library;
this one is where a name is looked up. <<reference-xstate-names>>, in
<<from-xstate-to-cpp>>, goes the other way, from XState's names to xstate's.
